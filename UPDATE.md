# Обновление FileShare

## Если вы уже установили FileShare

После внесения изменений в код (интеграция с backend API, хранение настроек в PostgreSQL), вам нужно обновить систему.

### Шаг 1: Остановите контейнеры

```bash
cd /opt/fileshare
docker compose down
```

### Шаг 2: Удалите старый volume с базой данных

⚠️ **Внимание:** Это удалит все данные! Если у вас есть важные файлы, сохраните их beforehand.

```bash
docker volume rm fileshare_postgres_data
```

### Шаг 3: Пересоберите и запустите контейнеры

```bash
docker compose build --no-cache
docker compose up -d
```

### Шаг 4: Проверьте работу

1. Откройте ваш сайт в браузере
2. Загрузите файл
3. Скопируйте ссылку
4. Откройте ссылку в другом браузере или в режиме инкогнито
5. Файл должен быть доступен! ✅

### Шаг 5: Проверьте настройки админки

1. Перейдите в админку по секретному URL
2. Измените настройки (размер файла, срок хранения, логотип)
3. Сохраните настройки
4. Перезагрузите страницу — настройки должны сохраниться ✅

## Альтернативный способ: Использование скрипта rebuild.sh

Если вы скачали обновлённый код из репозитория:

```bash
cd /path/to/FileSharing
sudo bash rebuild.sh
```

Этот скрипт автоматически:
- Остановит контейнеры
- Пересоберёт образы
- Запустит контейнеры
- Проверит здоровье сервисов

## Применение миграций к существующей БД

Если вы не хотите удалять данные, но хотите применить новые миграции:

```bash
cd /opt/fileshare
sudo bash apply-migrations.sh
```

Этот скрипт применит миграцию `002_admin_settings.sql` к существующей базе данных.

## Что изменилось

### 1. Интеграция Frontend с Backend API

**До:**
- Файлы хранились в localStorage браузера
- Ссылки работали только в том браузере, где файл был загружен
- Невозможно было обмениваться файлами между устройствами

**После:**
- Файлы хранятся на сервере (PostgreSQL + файловое хранилище)
- Ссылки работают из любого браузера/устройства
- Полноценный обмен файлами между пользователями

### 2. Хранение настроек админки в PostgreSQL

**До:**
- Настройки хранились в localStorage браузера
- Настройки были привязаны к конкретному браузеру
- При смене браузера настройки терялись

**После:**
- Настройки хранятся в PostgreSQL
- Настройки доступны из любого браузера
- Настройки сохраняются при смене устройства

### 3. API Endpoints для настроек

Добавлены новые endpoints:

```bash
# Получить настройки
GET /api/admin/settings

# Обновить настройки
PUT /api/admin/settings

# Сбросить настройки
POST /api/admin/settings/reset
```

## Проверка работы

### Проверка Backend API

```bash
curl http://localhost:3001/api/health
```

Должен вернуть:
```json
{
  "status": "ok",
  "timestamp": "2024-...",
  "version": "1.0.0"
}
```

### Проверка настроек админки

```bash
# Получить настройки
curl http://localhost:3001/api/admin/settings
```

Должен вернуть JSON с настройками.

### Проверка загрузки файла

1. Откройте сайт в браузере
2. Загрузите файл
3. Скопируйте ссылку
4. Откройте ссылку в другом браузере
5. Файл должен быть доступен

## Устранение проблем

### Backend не отвечает

Проверьте логи:
```bash
docker compose logs backend
```

### Frontend не подключается к Backend

Проверьте, что Vite proxy настроен правильно в `vite.config.js`:
```javascript
proxy: {
  '/api': {
    target: 'http://localhost:3001',
    changeOrigin: true,
  },
}
```

### Настройки не сохраняются

Проверьте, что миграция `002_admin_settings.sql` применена:
```bash
docker compose exec db psql -U fileshare -d fileshare -c "SELECT * FROM admin_settings;"
```

Должны быть строки с настройками.

### Файлы не доступны из другого браузера

Убедитесь, что:
1. Backend запущен и отвечает
2. Frontend подключается к Backend через proxy
3. В консоли браузера нет ошибок CORS
