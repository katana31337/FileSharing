# ⚡ Быстрая обработка ошибок

## 🎯 Что изменилось

Теперь при ошибке backend **frontend показывает ошибку пользователю**, а не молча переключается на localStorage.

## 🔍 Пример

### Было (плохо)

```
1. Пользователь загружает файл
2. Backend возвращает ошибку (нет колонки в БД)
3. Frontend молча переключается на localStorage
4. Пользователь видит "Файл загружен" ✅
5. Но на сервере файл НЕ сохранён ❌
6. При переходе по ссылке — "Не найдено" ❌
```

### Стало (хорошо)

```
1. Пользователь загружает файл
2. Backend возвращает ошибку с деталями
3. Frontend показывает toast-уведомление:
   ❌ Ошибка загрузки файла
   "document.pdf": Ошибка базы данных: Схема базы данных не соответствует ожидаемой
4. Пользователь видит проблему ✅
5. Может обратиться к администратору ✅
```

## 📊 Типы ошибок

### 🔴 Ошибка базы данных

**Сообщение:**
```
❌ Ошибка загрузки файла
"document.pdf": Ошибка базы данных: Схема базы данных не соответствует ожидаемой. Обратитесь к администратору.
```

**Решение:**
```bash
sudo bash fix-db-schema.sh
```

### 🔴 Ошибка доступа к хранилищу

**Сообщение:**
```
❌ Ошибка загрузки файла
"document.pdf": Ошибка доступа к хранилищу: Нет прав для записи файлов. Обратитесь к администратору.
```

**Решение:**
```bash
sudo chmod 777 /dataStore/files/
```

### 🔴 Недостаточно места

**Сообщение:**
```
❌ Ошибка загрузки файла
"document.pdf": Недостаточно места: На сервере закончилось свободное место. Обратитесь к администратору.
```

**Решение:**
```bash
df -h /dataStore
find /dataStore/files -type f -mtime +30 -delete
```

## 🎨 Toast уведомления

### Типы

- 🔴 **Error** — критические ошибки
- 🟡 **Warning** — предупреждения (частичная загрузка)
- 🔵 **Info** — информация
- 🟢 **Success** — успех

### Примеры

```typescript
// Ошибка
toast.error('Ошибка загрузки файла', `"${file.name}": ${errorMessage}`);

// Предупреждение
toast.warning('Частичная загрузка', `Успешно: 3, ошибок: 1`);

// Успех
toast.success('Файл загружен', `"document.pdf" успешно загружен`);
```

## 🔧 Для администратора

### Проверить логи

```bash
docker compose logs -f backend
```

### Проверить состояние

```bash
sudo bash full-diagnose.sh
```

### Проверить диск

```bash
df -h /dataStore
```

### Проверить права

```bash
ls -la /dataStore/files/
```
