# 🔍 Компонент BackendStatus

## 🎯 Что это?

Компонент `BackendStatus` отслеживает доступность backend сервера и отображает предупреждение пользователю, если сервер недоступен.

## 🔄 Как это работает?

### Проверка статуса
```
1. При загрузке страницы компонент запрашивает GET /api/health
   ↓
2. Если ответ 200 OK → статус "online"
   ↓
3. Если ошибка или таймаут → статус "offline"
   ↓
4. Проверка повторяется каждые 30 секунд
```

### Отображение предупреждения
```
Статус "checking" → Показывает "Проверка подключения к серверу..."
Статус "online"   → Ничего не показывает
Статус "offline"  → Показывает красное предупреждение
```

```

└─────────────────────────────────────────┘
```

### Если backend доступен
```
(ничего не показывается)
```

### Если backend недоступен
```

│ ⚠️ Сервер недоступен                    │
│                                         │
│ База данных временно недоступна.        │

│ попробуйте позже или обратитесь к       │
│ администратору.                    [✕]  │
└─────────────────────────────────────────┘
```

## ⚙️ Настройки

### Таймаут проверки
```typescript
AbortSignal.timeout(5000) // 5 секунд
```

### Интервал проверки
```typescript
setInterval(checkBackend, 30000) // 30 секунд
```

### Позиция на странице
```typescript
fixed top-4 left-1/2 transform -translate-x-1/2
```

## 🔧 Использование

Компонент уже добавлен в `App.tsx` и отображается на всех страницах:

```typescript
import BackendStatus from './components/BackendStatus';

export default function App() {
  return (
    <BrowserRouter>
      <BackendStatus />
      <Routes>
        {/* ... */}
      </Routes>
    </BrowserRouter>
  );
}
```

## 🧪 Тестирование

### Тест 1: Backend доступен
```
1. Запустите backend: npm run dev
2. Откройте сайт
3. Должно появиться "Проверка подключения..."
4. Через 1-2 секунды предупреждение исчезнет
```

### Тест 2: Backend недоступен
```
1. Остановите backend
2. Откройте сайт
3. Должно появиться красное предупреждение
4. Подождите 30 секунд
5. Проверка повторится автоматически
```

### Тест 3: Закрытие предупреждения
```
1. Остановите backend
2. Откройте сайт
3. Нажмите кнопку [✕] на предупреждении
4. Предупреждение исчезнет
5. Через 30 секунд проверка повторится
```

- ✅ Возможность закрыть предупреждение
- ✅ Автоматическая повторная проверка

### Для администраторов
- ✅ Пользователи знают о проблеме
- ✅ Меньше обращений в поддержку
- ✅ Автоматическая проверка каждые 30 секунд

## 🔒 Безопасность

### Что защищено?
- ✅ Таймаут 5 секунд (не блокирует UI)
- ✅ Проверка только health endpoint
- ✅ Не раскрывает внутреннюю информацию

### Рекомендации
- ✅ Health endpoint должен быть публичным
- ✅ Не требует аутентификации
- ✅ Возвращает только статус

## 📚 API Endpoint

### GET /api/health
Проверка работоспособности backend

**Запрос:**
```http
GET /api/health
```

**Ответ (успех):**
```json
{
  "status": "ok",
  "timestamp": "2024-12-18T12:00:00Z"
}
```

**Ответ (ошибка):**
```
HTTP 500 Internal Server Error
```
