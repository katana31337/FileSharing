# 🔐 Создание учётных данных администратора

## 🎯 Что изменилось

Раньше скрипт установки (`install.sh`) запрашивал и генерировал логин/пароль администратора, но эти данные **не использовались**, потому что:

1. Логин/пароль хранятся **только в localStorage** браузера
2. При первом входе в админку проверяется localStorage
3. Если там нет данных — показывается форма первичной настройки
4. Пользователь создаёт **новый** логин/пароль
5. Сгенерированные в install.sh данные оставались неиспользованными

## ✅ Новое поведение

Теперь:
1. Скрипт установки **НЕ запрашивает** логин/пароль
2. Скрипт запрашивает только **секретный путь** для админ-панели
3. При первом входе в админку показывается форма первичной настройки
4. Пользователь создаёт логин/пароль через веб-интерфейс
5. Эти данные сохраняются в localStorage и используются для входа

## 🚀 Как это работает

### Шаг 1: Установка

```bash
sudo bash install.sh
```

Скрипт спросит:
- Тип SSL сертификата
- Домен/IP адрес
- Email (для Let's Encrypt)
- **Секретный путь** (например: `my-secret-admin-2024`)

В конце установки вы увидите:
```
🔐 Админ-панель:

   URL:      https://fileshare.local/#/my-secret-admin-2024

💡 При первом входе в админ-панель вам будет предложено создать логин и пароль.
   Сохраните их в безопасном месте после создания!
```

### Шаг 2: Первый вход в админку

1. Откройте браузер
2. Перейдите по секретному URL: `https://fileshare.local/#/my-secret-admin-2024`
3. Увидите форму первичной настройки:
   - Поле "Логин" (минимум 3 символа)
   - Поле "Пароль" (минимум 12 символов, с требованиями к сложности)
4. Создайте логин и пароль
5. Нажмите "Создать учётные данные"

### Шаг 3: Вход

После создания учётных данных:
1. Увидите форму входа
2. Введите созданные логин и пароль
3. Нажмите "Войти"
4. Попадёте в админ-панель

## 🔒 Требования к паролю

При создании пароля через веб-интерфейс проверяются:

- ✅ Минимум **12 символов**
- ✅ Содержит **строчные буквы** (a-z)
- ✅ Содержит **заглавные буквы** (A-Z)
- ✅ Содержит **цифры** (0-9)
- ✅ Содержит **спецсимволы** (!@#$%^&* и др.)

## 💾 Где хранятся учётные данные

### Локально (в браузере)

Учётные данные хранятся в **localStorage** браузера:

```javascript
localStorage.getItem('fileshare_admin_settings')
// {
//   "adminLogin": "myadmin",
//   "adminPassword": "MySecurePass123!",
//   "adminSecretPath": "my-secret-admin-2024",
//   ...
// }
```

### На сервере

**Важно:** Логин/пароль **НЕ хранятся** на сервере!

В PostgreSQL хранятся только:
- Настройки (размер файлов, сроки хранения и т.д.)
- Секретный путь для админ-панели
- Метаданные файлов и текстов

## 🔄 Сброс учётных данных

Если вы забыли логин/пароль или хотите их изменить:

### Способ 1: Через консоль браузера

1. Откройте сайт в браузере
2. Нажмите F12 (консоль разработчика)
3. Перейдите на вкладку "Console"
4. Выполните команду:

```javascript
localStorage.removeItem('fileshare_admin_settings');
```

5. Перезагрузите страницу
6. Перейдите по секретному URL снова
7. Создайте новые учётные данные

### Способ 2: Очистка данных сайта

1. Откройте настройки браузера
2. Перейдите в "Конфиденциальность и безопасность"
3. Найдите "Очистить данные сайтов"
4. Выберите ваш сайт (например: `fileshare.local`)
5. Очистите данные
6. Перейдите по секретному URL снова
7. Создайте новые учётные данные

## 🛡️ Безопасность

### Плюсы

- ✅ Учётные данные создаются **вами** через защищённый веб-интерфейс
- ✅ Пароль проверяется на сложность
- ✅ Данные хранятся только в вашем браузере
- ✅ Никто не может узнать ваш пароль (даже администратор сервера)

### Минусы

- ⚠️ Если очистить localStorage — учётные данные потеряются
- ⚠️ Учётные данные привязаны к конкретному браузеру
- ⚠️ При использовании другого браузера нужно создавать учётные данные заново

### Рекомендации

1. **Сохраните учётные данные** в безопасном месте (менеджер паролей)
2. **Используйте сложный пароль** (12+ символов, буквы, цифры, спецсимволы)
3. **Не используйте одинаковые пароли** для разных сервисов
4. **Регулярно обновляйте пароль** через сброс и создание новых учётных данных

## 📊 Сравнение старого и нового подхода

| Аспект | Старый подход | Новый подход |
|--------|---------------|--------------|
| Запрос логина/пароля | ✅ В install.sh | ❌ Убран |
| Генерация пароля | ✅ В install.sh | ❌ Убрана |
| Вывод в конце установки | ✅ Показывает логин/пароль | ❌ Убран |
| Создание учётных данных | ❌ Не используются | ✅ Через веб-интерфейс |
| Хранение | ❌ Только в .env (не используется) | ✅ В localStorage |
| Безопасность | ⚠️ Пароль в .env файле | ✅ Только в браузере |
| Удобство | ❌ Путаница с данными | ✅ Понятный процесс |

## 💡 Почему это лучше

### Старый подход (проблемы)

1. Скрипт генерирует логин/пароль
2. Показывает их в конце установки
3. Пользователь должен их сохранить
4. Но при первом входе в админку — они не работают
5. Нужно создавать новые учётные данные
6. Старые данные оказываются бесполезными
7. Путаница и недоумение

### Новый подход (решение)

1. Скрипт НЕ запрашивает логин/пароль
2. Скрипт запрашивает только секретный путь
3. При первом входе — понятная форма создания учётных данных
4. Пользователь сразу создаёт рабочие данные
5. Никакой путаницы
6. Прозрачный и понятный процесс

## 🎯 Итого

**Учётные данные администратора теперь создаются при первом входе в админ-панель через веб-интерфейс.**

Это:
- ✅ Проще
- ✅ Понятнее
- ✅ Безопаснее
- ✅ Логичнее
